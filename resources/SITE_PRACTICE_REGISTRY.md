# Site Practice Registry (爆款二创 on yimiagent.cn)

These rules were proven on the production site while it ran on VIDEO_AGENT_EXECUTOR_V1 (2026-09-28 → 2026-10-04). They are registered here so that V2.2 is the single source of truth. All future workflow optimisations are recorded in this Skill. The rules are provider-neutral; concrete routing lives in `tools/router_mapping.yimiagent.json`.

## Ingest and analysis
1. **Shot split**: scene-change score > 0.32 marks a cut; very short shots merge into the previous one and very long shots split, giving 2–24 SOURCE shots. Results are cached per source video.
2. **Platform end cards are dropped**: OCR on the last two shots. Search pages, follow prompts and account pages (e.g. 「大家都在搜」「扫一扫」「关注我」) are excluded from analysis, generation, assembly and one-click. Per-frame platform watermarks alone do not count as end cards.
3. **Source audio profile (measured, not guessed)**: volume detection, local ASR (with a filter for music hallucinations), a 50 ms RMS envelope (music presence; transition-SFX rises at cuts), and local sound-event classification (genres, instruments, timed SFX events, speaker gender). The result is stored as `job.audio`.
4. **One analysis pass shares one GLOBAL MASTER**: step 1 reads all keyframes and sets structure plus masters. Step 2 writes per-shot plans in parallel groups of 3 that share the step-1 master. Do not split the master per group (this broke cross-shot consistency). An incomplete group is redone once, then fails explicitly; frames are never filled by position or with defaults.
5. **Recreation strength per task**: 保守 / 中度 / 大胆, chosen next to the analysis model (default 保守) and stored as `job.mode`. Image, video, QA and redo all follow the task's mode. The user's 拆解要求 text overrides the mode.
6. **Structure lock** (保守/中度): subject, left/right hand and gesture, face visible or not, subject orientation, camera angle, shot size and composition stay as in the source; no mirroring.

## Text and compliance
7. **Reference frames are de-burned**: OCR text boxes are removed (or the analysed `text_band` is blurred) before a source keyframe is used as a generation reference. QA still compares against the original frame.
8. **Platform text sanitizer**: account names, platform names, search/follow prompts and IDs are removed from subtitles and voice-over.
9. **Voice-over follows the source**: lines are written only where the source has speech, rewritten to a similar length; subtitle = voice-over. On-screen copy without speech is recreated in the same language, at a similar length, with the same function, and is shown at the source text position (`text_band`).

## Generation
10. **Presence-filtered masters in video prompts**: only masters present in the segment are bound. Elements absent from every shot in the segment are forbidden from the first frame to the last (no product appearing at the end of a search-page shot).
11. **Product reference reuse**: the first QA-passed product shot becomes an extra product reference for later product shots.
12. **Segments**: video is generated per segment (`shotGroup`, labelled 第N段). Adjacent shots merge into one segment (span ≤ 10 s, ≤ 4 shots, generated ≤ 12 s). The first frame is the segment's first recreated keyframe; models without last-frame support receive the other keyframes as references.
13. **Native audio (V2.2.1)**: each segment prompt ends with a 【声音】 block (voice-over lines, voice identity, source-like SFX, source-like but newly composed BGM). A silent source gives a silent segment.

## QA and retry
14. **Vision QA on every recreated image** with fail codes `FAIL_STRUCTURE, FAIL_UNAUTHORIZED_CHANGE, FAIL_EXTRA_HAND, FAIL_PRESENCE, FAIL_COLLAGE_OUTPUT, FAIL_UNAUTHORIZED_TEXT, FAIL_PRODUCT_GEOMETRY, FAIL_COPY_SOURCE, FAIL_INSUFFICIENT_CREATIVE_DELTA, FAIL_SEMANTIC_FUNCTION, FAIL_STYLE_DRIFT, FAIL_BLURRY, FAIL_LIGHTING`. Each mode defines which codes apply.
15. **Video QA** (V2.2.2): each segment gets audio checks (audio present, planned lines spoken, no unplanned speech) and visual checks on 3 frames (`FAIL_NO_AUDIO, FAIL_MISSING_DIALOGUE, FAIL_DIALOGUE_MISMATCH, FAIL_UNPLANNED_SPEECH, FAIL_PRESENCE, FAIL_UNAUTHORIZED_TEXT, FAIL_COLLAGE_OUTPUT, FAIL_EXTRA_HAND, FAIL_PRODUCT_GEOMETRY, FAIL_IDENTITY_DRIFT, FAIL_SEMANTIC_FUNCTION, FAIL_BLURRY`). Missing BGM is recorded as a note.
16. **Redo with learning** (V2.2.4): the redo dialog auto-drafts a revised scene from the QA reason (editable) and allows replacing reference 2. Every redo outcome is logged as a skill lesson for periodic review into this Skill.
17. **No automatic retry**: a failed frame shows its reason and a manual 重做 button. A redo appends only the targeted fixes for the failed codes, does not rewrite the prompt, and is billed normally.

## Assembly and canvas
18. **Final edit mirrors source timing**: each segment is trimmed or slowed (up to 0.8× speed, audio time-stretched), then frozen to the source shot duration. Transitions follow the source; subtitles align to the spoken lines; recreated on-screen text is placed at the source text position.
19. **One-click** runs server-side as hidden tasks. The synced canvas shows only visible workflow items (it prefers visible tasks and excludes one-click hidden ones).
20. **Synced canvas** has fixed nodes and edges: source keyframe → recreated image → segment video → FFmpeg final edit → final film. The user may replace materials and edit prompts, models, parameters and subtitles. There is no BGM node since V2.2.1.
21. **Subtitle style** (V2.2.7): no full stop at the end of any subtitle line (a full stop between sentences becomes a space; ？！ and ellipses kept). Fixed style since V2.2.8 (supersedes the one-third rule): 1080×1920 reference, 思源黑体 Bold 54, white, outline 3, shadow 1, bottom-centre, MarginV 300, MarginL/R 60, scaled for other sizes.
22. **ASR hallucination filter** (V2.2.7): Whisper segments containing platform stock phrases (请点赞、订阅、转发、打赏、感谢观看、字幕由…提供 …) are dropped before subtitles and dialogue QA. Field case: 《玻璃塔的早晨》 got 「请点赞,订阅,转发,打赏」 burned in at 29 s over a music-only coffee shot.
23. **Standard edit output** (V2.2.7): 1080×1920 / 1920×1080, 30 fps, CRF 18 preset medium; a user bitrate is floored at ≈8 Mbps for 1080p. Field case: an edit plan read "1 Mbps" from the user's script and the 1080p output was visibly blocky.
24. **漫剧 self-check** (V2.2.7): every 漫剧创作 image/video is checked on 人物 (same face, hair, clothing, age as the reference images and earlier shots), 景 (same location keeps architecture, props, light, palette, style) and, for video, 声音 (audio present, quoted 台词 spoken, no speech when 台词：无). Mark only; the user can 重做 (normal price), which appends targeted fixes and is logged as a skill lesson.
25. **Single editing module** (V2.2.8): every workflow's final cut goes through `postproduction.mjs` (爆款二创 → startSynthesis; 漫剧创作 / 图生视频 / 只剪辑合成 / canvas → startCanvasSynthesis). Editing-rule updates are made only there, so they apply to every workflow at once.
26. **中度 style & motif lock** (V2.2.9): 中度 keeps palette, theme and scene category, product-linked symbolic motifs and mood, and replaces only same-category, same-colour instances. Field case: 《爆款二创 2026/10/6 06:10:39》 (bracelet + red knit sleeve + red temple + Buddha = blessing/luck). The old 中度 rule replaced the environment with a "modern oriental still-life space, no ancient buildings or Buddha", a cream sleeve and a blue-grey palette. The structure matched, but the style and the meaning were lost.
27. **Edit-plan confirmation in 爆款二创** (V2.2.9): the 剪辑合成 button opens the plan dialog (transitions default to 跟随原视频). Charging happens only on confirm.
28. **Visual parameter checklist** (V2.2.10): each source shot records `visual` (lighting / lighting_plan / lens + focus point / texture / weather_time / props / camera_move / subject_move / pace). Prompts compile it as natural language, in priority order, plus fixed quality blocks. Camera motion and subject motion are always written separately, and each shot has a single light (`lighting_plan`, bounded by the mode). Field motivation: recreated frames missed details, drifted, or came out soft; the structure lock and style lock had no light, lens, texture or quality terms.
29. **中度 / 大胆 per-shot plans wait for the global master; 换一版** (V2.2.11). Parallel per-shot planning is only for 保守 with no replacement wording. Field case: 《爆款二创 2026/10/6 23:10:29》 came out identical to the source, because the shots were planned with a "keep everything" placeholder. 「换一版」 rewrites one shot within the mode's allowed scope, and each click gives a new version.
30. **Film-wide look & product anchors; sync look** (V2.2.12). Before this version, only the product had an image anchor. Person and clothing were consistent only in text, so faces and outfits drifted between frames, and an edit to one frame didn't reach the others. Now there are look and product anchors (auto or user-set, including an uploaded reference), an AI sync that rewrites only the look wording in the other frames, and the QA code `FAIL_LOOK_DRIFT`.
31. **User edits win** (V2.2.13). Field case: the user added 「修改连衣裙颜色：粉紫色、灰蓝色、米白色」 to frame 1, but the style lock, film-wide master, 禁止 palette clause, reference-1 note, look anchor and QA all enforced the source colour, so the dress never changed. The edit diff is now compiled as the highest-priority block, conflicting constraints are relaxed, and QA checks that the edit was applied.
32. **Breakdown request first** (V2.2.14). Field request: 中度/大胆 + 「给小孩换个脸的造型、裙子换款颜色、猫换个颜色、场景换个同类风格，其他不变」. Before this version, the request sat at the end of the instructions, below "人物/手部 PRESERVE" and the palette lock, so it was treated as a hint. Now named elements are replaced, everything else is kept, and the requests are carried into every prompt and QA check.
33. **Mode policy confirmed by the user** (V2.2.15). 保守 is a full replica. Before this version, 保守 invented light, time and foreground changes, and QA demanded "creative change". 中度 replaces product, person / hand, clothing, scene, props and sound with same-category, same-colour new models; before, it kept product and person. 大胆 also gives the product a same-category new design. User-specified prompts and references always win.
34. **Anchor first, manual edits film-wide, machine-readable policy** (V2.2.16). The user asked that a film reference outrank prompts, so frames whose prompts omit or contradict the look still follow it. They also asked that hand-made changes (person, colour, product) stay consistent in every frame, and that the rules be machine-readable rather than prose. Implemented as `film_anchor` rank 2, `job.film_edits`, and `specs/recreation_policy.json`.
35. **Copy per mode + speech-to-picture sync** (V2.2.17). The user chose B (light synonym edit) for 保守. For 中度 they required that a rewritten line like 「开门」 is spoken while the door opens. Before this version, the video prompt only said "say these lines within the segment".
36. **Brand end card → own end shot + www.yimiagent.cn** (V2.2.18, user rule 2026-10-07). Applies in every mode. Before this version, 保守/中度 locked the structure of the source's 抖音 search or brand card and recreated it.
37. **One-click = same mode policy** (V2.2.19). User rule: one-click under 保守 / 中度 / 大胆 must produce visuals, sound, lines, subtitles and the end card by that mode's rules. Fixed in this version: a resume used to reuse an analysis made under another mode, and person / clothing had no lead shot.
38. **Anchor must win everywhere in the prompt** (V2.2.20). Field case: 《爆款二创 2026/10/6 23:10:29》. Frames 1–2 followed the red-dress anchor. Frame 3 stayed in the striped dress because (a) the product-reference text said not to copy the person in reference 2, and (b) 「横条纹连衣裙」 was still in 二创画面, 结构锁定 and 保留. Frame 4 (adult clipping a crying toddler's nails) was blocked by GPT-Image-2's safety review. That is an upstream policy issue, not a rule issue.
39. **Video prompts must match the confirmed images** (V2.2.21). Field case: the frame-1 dress was edited to red and frame 1 was set as the anchor, so all images turned out red. But the edited prompt was lost after re-entry, and the video prompts still said 「横条纹连衣裙」. Fixed with persisted prompts, the 首帧为准 rule in video prompts, and 「按图片更新提示词」.
